# 巡展作品光照预算 Web 工作台

为巡展作品管理展期曝光预算的本地 Web 工具：Node.js + SQLite + 浏览器页面，单机本地运行。

- **作品维度**：录入展期曝光上限与既有累计量，实时显示已用 / 预占 / 余额（单位 lux·min）。
- **时段维度**：为展厅时段录入起止时间、照度（lux）和展出作品，按 **实际经过分钟 × 照度** 计算曝光。
- **临时闭馆暂停 / 恢复**：进行中时段遇临时闭馆可**暂停**，开馆后**恢复**，允许多次。每次暂停（或最终结束）都提交**当前展出区间的起止 + 完整衔接照度分段**；暂停空档不计曝光，已完成区间计入已用并**释放未展预占**；恢复时提交恢复时间与新预计结束，从恢复时间起按**新时长 × 计划照度**重新预占，并重算作品余额与后续时段缺口。
- **多段照度结算**：巡展时段的实际照度可能随时间变化。进行中时段可按实际起止提交**多段照度**完成结算，曝光 = Σ（各段实际分钟 × 段照度）；每段含起止与非负照度，分段须首尾衔接、无重叠且完整覆盖实际区间，否则**整批拒绝**。
- **分段更正**：已结束时段可按**原实际起止**（暂停模型按原各展出区间）提交带理由的完整分段更正；记录更正前后曝光和时间，**新总量替换旧总量、不重复累计**，并同步重算作品已用量、后续时段不可启动状态与缺口。
- **整批排期**：未开始时段在草稿中统一编辑后整批提交；同一作品时段重叠、或“已用 + 预占”超上限时 **拒绝整批**，逐条指出冲突作品与时段。
- **生命周期**：时段开始即冻结原排期并保留预占；临时闭馆可暂停（提交当前区间分段、释放未展预占）并恢复（按新预计重新预占，可多次）；结束时补记实际起止与照度（单一照度或多段；暂停模型只结最后区间），**实际曝光替换该时段预占**；结算超量后按开始时间/编号顺序标出不可启动时段与缺口并禁止启动。
- **乐观并发**：所有调整（含暂停、恢复、多段结算与分段更正）携带当前版本号，过期版本返回 409 与最新预算，失败不改变状态、账目和版本。

## 一键启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

启动后打开：

- **页面地址**：http://localhost:8080
- 初始化：首次启动自动建表并写入演示数据（3 件作品 + 已结束/进行中/已暂停/未开始时段；已暂停时段「四号厅」可直接点恢复体验）。

如需更换宿主机端口：

```bash
PORT=9090 docker compose up -d --build   # 页面变为 http://localhost:9090
```

停止与重置初始数据：

```bash
docker compose down            # 停止，数据保留在命名卷中
docker compose down -v         # 同时删除数据卷，下次启动重新初始化
```

## 本地直接运行（需要 Node.js ≥ 20）

```bash
npm install
npm start
# 打开 http://localhost:8080
```

## 计算与校验规则

- **曝光量** = （结束 − 开始，分钟）× 照度 lux，单位 **lux·min**。
- **已用** = 作品既有累计量 + 所有已结束时段的**实际**曝光 + 进行中/已暂停时段**已完成展出区间**的曝光。
- **预占** = 进行中时段当前展出区间的预占（暂停前为冻结计划曝光；恢复后为 **（新预计结束 − 恢复时间）× 计划照度**）+ 所有未开始时段的计划曝光之和；**已暂停时段不预占**（空档释放）。
- **余额** = 上限 − 已用 − 预占；余额为负即超量。
- 排期整批保存时校验：
  1. 时间格式合法、结束晚于开始、照度/累计量非负（无效时序或负值一律拒绝）；
  2. 同一作品在任意两个未开始时段、以及与进行中（冻结区间）/已结束（实际区间）时段之间不得重叠；
  3. 每件作品「既有 + 已结束实际 + 进行中预占 + 本批未开始预占」不得超过展期上限。
- 任一条不满足则整批不落库，响应中给出作品、冲突时段对或超量数值。
- **不可启动核算**：每次调整/启动/结算/分段更正后，未开始时段按开始时间（再按编号）顺序尝试占用预算；任一关联作品余额不足即标记为“不可启动”并列出每件作品的可用余额、需求与缺口，启动接口对该时段返回 422。调整排期保存后自动重新核算。
- **多段照度结算（进行中时段）**：
  1. 必须携带当前 `version`；实际开始早于实际结束；
  2. `segments` 为非空数组，每段含 `start`、`end`（合法时间，结束晚于开始）与非负 `lux`；
  3. 按提交顺序，第一段起点必须等于实际开始、相邻段首尾必须相接（前段 `end` = 次段 `start`）、最后一段终点必须等于实际结束——即**无重叠、无缺口、完整覆盖**；
  4. 曝光 = Σ（段分钟 × 段照度），替换该时段预占并触发不可启动重算；
  5. 任一段非法或不满足衔接/覆盖 → `422 SEGMENTS_INVALID` 并逐条给出原因，**整批拒绝，结算与版本均不变**；版本过期 → `409 VERSION_STALE` 与最新预算。
  6. **曾暂停的时段**最终结束仍走本接口：只提交**最后一个展出区间**（从恢复时间开始）的分段，`actualStart` 可省略（服务端以恢复时间为准），`actualEnd` 为最终结束；已完成区间曝光已累计，暂停空档不计。
- **临时闭馆暂停 / 恢复（进行中时段）**：
  1. **暂停** `POST /api/slots/:id/pause`：body `{version, actualStart?, pauseEnd, segments}`。
     首次暂停可录本段实际开始 `actualStart`（缺省取冻结计划开始）；再次暂停该字段必须等于当前恢复时间（可省略）。
  2. 分段规则与多段结算一致：非空、非负照度、首尾衔接、无重叠、完整覆盖 **[本段起点, 暂停时间]**；暂停时间必须晚于本段起点、晚于上一次暂停终点；不合法 → `422 SEGMENTS_INVALID` / `422 VALIDATION`，**整次拒绝，状态、账目与版本不变**。
  3. 暂停后时段状态变为 `paused`：本区间 Σ 曝光计入**已用**（累计曝光），**释放**原“暂停时间之后”的未展预占，暂停空档不预占、不计曝光。
  4. **恢复** `POST /api/slots/:id/resume`：body `{version, resumeAt, newEstimatedEnd}`。恢复时间必须**严格晚于**上次暂停终点，新预计结束必须晚于恢复时间；恢复后状态回到 `running`，从恢复时间起按 **（新预计结束 − 恢复时间）× 计划照度**重新预占，并重算余额与后续未开始时段的不可启动状态/缺口（预占超额时允许恢复但会标出受影响的后续时段）。
  5. 暂停或恢复的区间与**同作品其他时段**（含未开始计划区间、其他时段的已完成/预占区间）重叠时 → `422 OVERLAP_CONFLICT` 并列出冲突作品与时段，整次拒绝。各展出区间按时间递增、互不重叠，区间间的暂停空档可被同作品其他时段使用（端点相接允许）。
  6. 允许多次暂停；每次成功变更版本 +1。最终结束走多段结算（只覆盖最后区间），结束后 `actualExposure` 为全部展出区间 Σ（暂停空档不计）。
  7. 已暂停时段不能暂停/结束/结算（须先恢复）；未暂停或已结束时段不能恢复。使用过暂停/恢复的时段不能再用单一照度 `finish`（返回 `422 SEGMENTS_REQUIRED`）。
- **分段更正（已结束时段）**：
  1. 必须携带当前 `version` 与非空 `reason`（≤200 字）；
  2. 实际区间沿用时段**原实际起止，不可更改**；提交的完整分段须按上述同样规则覆盖该区间；
  3. **曾暂停的时段**（`intervals` 非空）须用 `intervalSegments: [{segments:[…]}]` **逐展出区间**分组提交，每组完整覆盖对应区间（暂停空档无需分段）；分组数与区间数不符或任一组非法 → `422 SEGMENTS_INVALID` 整批拒绝；
  4. 新曝光总量**替换**旧总量（非累加），同步重算作品已用量、后续时段不可启动状态与缺口；
  5. 每次更正留痕：更正前后的实际起止、曝光总量、理由、所基于版本、时间戳及“更正后分段”快照（暂停模型展平各区间分段），可在页面「分段更正记录」中查看，也随该时段在 `GET /api/state` 的 `corrections` 字段返回。
- **并发版本**：每次成功变更版本号 +1。请求必须携带当前 `version`；不匹配时返回 `409 VERSION_STALE` 与最新完整预算，前端自动刷新后需重新调整提交。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 最新版本、作品预算汇总、全部时段（含 `actualSegments` / `intervals` / `corrections`）及不可启动核算结果 |
| POST | `/api/artworks` | 录入作品（body 带 `version`） |
| PUT | `/api/artworks/:id` | 修改作品上限/既有量等 |
| DELETE | `/api/artworks/:id` | 删除作品（被时段引用时拒绝） |
| POST | `/api/schedule` | **整批替换未开始时段**（body：`{version, slots:[...]}`） |
| POST | `/api/slots/:id/start` | 启动时段：冻结原排期、保留预占 |
| POST | `/api/slots/:id/pause` | **临时闭馆暂停**：`{version, actualStart?, pauseEnd, segments}`，提交当前展出区间与完整分段 |
| POST | `/api/slots/:id/resume` | **恢复展出**：`{version, resumeAt, newEstimatedEnd}`，按新时长×计划照度重新预占 |
| POST | `/api/slots/:id/finish` | 结束补记（未使用暂停的时段）：`{actualStart, actualEnd, actualLux}` 单一照度结算，无需版本 |
| POST | `/api/slots/:id/settle` | **多段照度结算（进行中）/ 暂停模型最终结束**：`{version, actualStart?, actualEnd, segments:[…]}` |
| POST | `/api/slots/:id/correct` | **分段更正（已结束）**：`{version, reason, segments}` 或暂停模型 `{version, reason, intervalSegments}`，区间沿用原实际起止 |

### 临时闭馆暂停 / 恢复：HTTP 调用示例

假设时段 `#6` 计划 `09:00–12:00`（180 分 × 100 lux = 18000 预占），09:10 才实际开馆，10:00 临时闭馆暂停：

```bash
curl -s -X POST http://localhost:8080/api/slots/6/pause \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 4,
    "actualStart": "2027-01-10T09:10",
    "pauseEnd":    "2027-01-10T10:00",
    "segments": [
      { "start": "2027-01-10T09:10", "end": "2027-01-10T09:40", "lux": 120 },
      { "start": "2027-01-10T09:40", "end": "2027-01-10T10:00", "lux": 180 }
    ]
  }'
```

本区间 30×120 + 20×180 = **7200** 计入已用，10:00 之后的未展预占被释放。返回完整预算状态，另含
`justPausedInterval`、`cumulativeExposure`（累计曝光）、`releasedReservation` 与重算后的
`blockedAfterFinish`；时段状态变为 `paused`，`currentReserved` 为 0。

10:30 重新开馆，新预计 11:30 结束（60 分 × 100 = **6000** 重新预占）：

```bash
curl -s -X POST http://localhost:8080/api/slots/6/resume \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 5,
    "resumeAt":         "2027-01-10T10:30",
    "newEstimatedEnd":  "2027-01-10T11:30"
  }'
```

返回 `resumeAt`、`newEstimatedEnd`、`reservedExposure`（6000）与完整预算状态。可多次暂停；
最终结束时只提交**最后一个展出区间**的分段（无需 `actualStart`，服务端以恢复时间为准）：

```bash
curl -s -X POST http://localhost:8080/api/slots/6/settle \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 8,
    "actualEnd": "2027-01-10T11:20",
    "segments": [
      { "start": "2027-01-10T10:30", "end": "2027-01-10T11:00", "lux": 100 },
      { "start": "2027-01-10T11:00", "end": "2027-01-10T11:20", "lux": 160 }
    ]
  }'
```

时序 / 分段 / 重叠不合法均整次拒绝（`422 VALIDATION` / `SEGMENTS_INVALID` / `OVERLAP_CONFLICT`），
版本过期返回 `409 VERSION_STALE` 与最新预算；失败时状态、账目与版本均不变。`OVERLAP_CONFLICT` 形如：

```json
{ "error": { "code": "OVERLAP_CONFLICT", "message": "整次已拒绝：与同作品其他时段占用区间重叠" },
  "conflicts": [ { "artworkId": 3, "artworkName": "《青铜纹样》摄影", "kind": "overlap-reserve",
    "other": { "slotId": 12, "hall": "七号厅", "status": "scheduled",
      "start": "2027-01-10T12:30", "end": "2027-01-10T13:00",
      "label": "七号厅 2027-01-10T12:30 ~ 2027-01-10T13:00（未开始）" } } ] }
```

`GET /api/state` 中暂停/恢复时段在普通字段之外另返回区间明细（`actualSegments` 为跨空档展平视图）：

```json
{
  "id": 6, "status": "paused", "pauseCount": 1,
  "cumulativeExposure": 7200, "currentReserved": 0,
  "actualStart": "2027-01-10T09:10", "actualEnd": "2027-01-10T10:00",
  "intervals": [
    { "index": 1, "start": "2027-01-10T09:10", "end": "2027-01-10T10:00",
      "plannedEnd": "2027-01-10T10:00", "plannedLux": 100, "active": false,
      "exposure": 7200, "reserved": 0,
      "segments": [ /* {index,start,end,minutes,lux,exposure} … */ ] }
  ],
  "actualSegments": [ /* 各区间分段按时间展平，附 intervalIndex；区间间空档自然断开 */ ]
}
```

恢复后（`status:"running"`）会多一条 `active:true`、`end:null` 的区间，并以 `reserved`
（恢复时间→新预计结束×计划照度）作为当前预占；最终结束后所有区间 `active:false`，
`actualExposure` 为各区间曝光之和。

### 多段结算与分段更正：HTTP 调用示例

先取当前版本：

```bash
curl -s http://localhost:8080/api/state | jq '.version, .slots[] | {id,status}'
```

进行中时段按多段实际照度结算（09:00–11:00 为 200 lux，11:00–13:00 降为 100 lux）：

```bash
curl -s -X POST http://localhost:8080/api/slots/2/settle \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 1,
    "actualStart": "2026-09-30T09:00",
    "actualEnd":   "2026-09-30T13:00",
    "segments": [
      { "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 200 },
      { "start": "2026-09-30T11:00", "end": "2026-09-30T13:00", "lux": 100 }
    ]
  }'
```

返回为完整预算状态，另含：`justFinishedExposure`（总量 36000 = 120×200 + 120×100）、
`justFinishedSegments`（各段分钟/照度/曝光）、`blockedAfterFinish`（结算后被标不可启动的后续时段及缺口）。

分段不合法（缺口/重叠/未覆盖/负值）时返回 `422 SEGMENTS_INVALID`：

```json
{ "error": { "code": "SEGMENTS_INVALID", "message": "整批已拒绝：照度分段不合法…" },
  "errors": ["第 2 段：照度必须为非负数值", "分段在 … 之间存在缺口，分段必须首尾衔接"] }
```

对已结束时段按原实际起止提交带理由的完整分段更正：

```bash
curl -s -X POST http://localhost:8080/api/slots/1/correct \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 3,
    "reason": "照度计复核：开场一小时 100 lux，之后恢复 150 lux",
    "segments": [
      { "start": "2026-09-29T09:10", "end": "2026-09-29T10:10", "lux": 100 },
      { "start": "2026-09-29T10:10", "end": "2026-09-29T11:50", "lux": 150 }
    ]
  }'
```

返回完整预算状态，另含 `correction`（更正记录）、`beforeExposure` / `afterExposure`、
`blockedAfterFinish`。版本过期时两接口均返回 `409` 与最新预算：

```json
{ "error": { "code": "VERSION_STALE", "message": "版本已过期：当前版本 v4…" },
  "state": { "version": 4, "artworks": [], "slots": [] } }
```

`GET /api/state` 中已结算时段结构（旧单一照度结算会合成单段）：

```json
{
  "id": 1, "status": "finished",
  "actualStart": "2026-09-29T09:10", "actualEnd": "2026-09-29T11:50",
  "actualLux": null, "actualExposure": 21000,
  "actualSegments": [
    { "index": 1, "start": "2026-09-29T09:10", "end": "2026-09-29T10:10", "minutes": 60,  "lux": 100, "exposure": 6000 },
    { "index": 2, "start": "2026-09-29T10:10", "end": "2026-09-29T11:50", "minutes": 100, "lux": 150, "exposure": 15000 }
  ],
  "corrections": [
    { "id": 1, "reason": "…", "baseVersion": 2, "createdAt": "2026-09-30T12:00:00.000Z",
      "before": { "start": "…", "end": "…", "exposure": 22400 },
      "after":  { "start": "…", "end": "…", "exposure": 21000, "segments": [ /* 同上分段快照 */ ] } }
  ]
}
```

## 页面用法（本轮新增）

- **进行中 / 已暂停 / 已结束时段**表新增暂停状态与「累计曝光 / 当前预占」列；进行中时段有 **结束补记 / ⏸ 暂停** 两个操作，已暂停时段有 **▶ 恢复展出**。
- 点 **⏸ 暂停**：弹窗确认本段起点（首次可改录实际开始，再次暂停固定为恢复时间）与暂停时间，编辑覆盖本区间的完整照度分段，实时显示本区间 Σ 曝光；提交后时段变为「已暂停·闭馆」，页面按区间展示分段并标注**暂停空档（不计曝光、不预占）**。
- 点 **▶ 恢复展出**：填写晚于上次暂停终点的恢复时间与新预计结束，弹窗实时显示按新时长 × 计划照度的新预占；恢复后状态回到进行中（徽章显示“已恢复”）。
- 曾暂停的时段点 **结束补记**：自动锁定为多段模式，只需编辑**最后一个展出区间**（起点锁定为恢复时间）的分段；已完成区间已计入累计。
- **进行中 / 已结束时段**表的“计划/展出区间 / 分段”“分段照度”“累计曝光 / 当前预占”三列展示分段明细；未使用暂停的旧时段仍按原单段展示。
- 已结束时段点 **分段更正**：未暂停过的时段保持单一编辑器；曾暂停的时段按**展出区间分组**编辑（每组覆盖对应区间，空档无需分段），实时汇总更正后曝光。
- 已结束时段点 **分段更正**（旧链路）：弹窗显示原实际区间（不可改），填写理由并提交完整分段；成功后页面顶部提示更正前后曝光，作品已用量与后续不可启动状态即时刷新。
- 页面新增 **分段更正记录** 卡片：按时间倒序展示每次更正的理由、实际区间、更正前后曝光、变化量与更正后分段。

## 快速体验超量拦截

初始演示数据以 2026-09-30 为当天，预算均充足。进入页面：

1. 对「一号厅 09:00–13:00（进行中）」点 **结束补记**；
2. 把实际照度改为 `300`（240 分钟 × 300 = 72000 lux·min），保存；
3. 后续二号厅时段会被标记为 **不可启动**，页面列出《山水轴》《星夜手稿》的缺口，启动按钮被禁止；
4. 在未开始排期草稿中缩短时长 / 降低照度 / 改展作品后 **整批校验并保存**，缺口消除即可重新启动。
